# Never ignore site/ in .gitignore, because the committed site/ is what gets deployed

## Context
A mkdox2 regeneration put `site/` in `.gitignore`. New built files were never committed, so the live site lost its CSS/JS and new pages returned 404.

## Options considered
- Ignore site/ and build in CI: contradicts the build-locally decision
- Track site/ (done): the committed output is exactly what is served

## Decision
Never ignore site/ in .gitignore, because the committed site/ is what gets deployed

## Consequences
After any mkdox2 upgrade, check that `.gitignore` doesn't contain `site/`. A missing CSS/JS bundle on the live site is the symptom.
