# Deploy GitHub Pages on push to main touching site/, without a CI build

## Context
`site/` is built locally and committed. Pages' branch mode can only serve `/` or `/docs` (and `docs/` holds the sources), so a GitHub Actions workflow has to publish `site/`.

## Options considered
- Push to `main` with `paths: ['site/**']` plus `workflow_dispatch`: content-only commits without a rebuild don't redeploy
- Every push to `main`: simpler, but redeploys identical output for todo or docs-only commits

## Decision
Deploy GitHub Pages on push to main touching site/, without a CI build

## Consequences
`.github/workflows/pages.yml` uploads `site/` unchanged (upload-pages-artifact → deploy-pages) with no Python or zensical in CI. If `docs/` changes are pushed without rebuilding, nothing is published, so always rebuild before pushing.
