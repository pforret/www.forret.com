# Accept that mkdox2 build commits and pushes, so build equals publish

## Context
`mkdox2 build` always runs `git add`, then `git commit` and `git push`, because its `-z "$GITPUSH"` check treats the default `0` as set. With Pages deploying on push, every build becomes a publish.

## Options considered
- Accept it: build = publish, which matches the build-locally workflow
- Fix mkdox2 so `-G` is needed to push: cleaner, but it's a separate repo and change
- Never use `mkdox2 build` here and only use plain `docker run ... build`: safe, but loses the wrapper

## Decision
Accept that mkdox2 build commits and pushes, so build equals publish

## Consequences
Use `mkdox2 build` only when you mean to publish. For a test build use `docker run --platform linux/amd64 --rm -v "$PWD":/docs pforret/mkdox-zensical build`, which doesn't commit. If mkdox2 is fixed later, this decision can be superseded.
