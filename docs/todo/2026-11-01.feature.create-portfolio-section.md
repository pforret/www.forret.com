# Create portfolio section from blog portfolio and GitHub repos

## Request
create portfolio based on https://blog.forret.com/portfolio/ and https://github.com/pforret?tab=repositories

## Analysis
This is a new feature: the site has no portfolio content yet. `docs/` only holds `index.md`, `about/`, `blog/`, `tags.md` and the scaffold assets. A new top-level folder `docs/portfolio/` becomes its own navigation tab (`navigation.tabs`).

Sources, as checked on 2026-11-01:
- **blog.forret.com/portfolio/** lists only 2 projects, with no descriptions on the overview page: **DCProof** (`/portfolio/dcproof/`) and **toolstud.io** (`/portfolio/toolstud_io/`). The detail pages need to be fetched for the text.
- **github.com/pforret** has 208 public repos, mostly Bash. The ones with the most stars are bashew (297★), m1_homebrew (56), LearnBashQuickly (37), crontask (32), setver (26), progressbar (25), wp_cleanup (15), bumpkeys (10), splashmark, shmixcloud, rexec, note, m1fusion, shtext, shlorem, shwordle, shini, font, mkdox, PeakClaude and others. 208 is far too many to list one by one, so this needs a selection and grouping.

Open questions:
- Selection: list by star threshold (for example ≥ 5★), or hand-pick?
- Layout: one page per flagship project (DCProof, toolstud.io, bashew), plus a grouped overview of the open-source tools (bash tooling, macOS setup, media, AI and images)? Or a single page made of cards (Material `grid cards`, which needs `attr_list` and `md_in_html`, both already enabled)?
- Static or refreshable: write the repo list by hand, or generate it with a script (`gh api`) so the star counts stay current?
- Should the blog's ideas and software categories (`/category/repo/`) feed into it as well?

Risks: the star counts and descriptions go stale. Fetched blog text may need rewriting rather than copying.

## Impacted files
- `docs/portfolio/index.md`: overview page (intro, flagship projects, grouped OSS tools as cards)
- `docs/portfolio/<project>.md`: detail pages for the flagship projects (DCProof, toolstud.io, bashew, …)
- `docs/portfolio/.pages`: order and title of the tab (awesome-pages)
- `docs/index.md`: link to the portfolio from the home page (the home page is still scaffold text)
- `zensical.toml`: add `portfolio/*.md` to the `llmstxt` sections

## Plan
1. Fetch the DCProof and toolstud.io detail pages from blog.forret.com and pull out the descriptions, roles, dates and links.
2. Pull the repo metadata with `gh api users/pforret/repos --paginate` (name, description, stars, language, topics, pushed date), leaving out forks.
3. Decide the selection and grouping (see the open questions) and record it as a decision.
4. Create `docs/portfolio/index.md` with an intro, a flagship section and grouped tool cards linking to GitHub.
5. Create a detail page for each flagship project.
6. Add `.pages` ordering, link it from `docs/index.md` and add it to the `llmstxt` sections.
7. Build with `docker run --platform linux/amd64 --rm -v "$PWD":/docs pforret/mkdox-zensical build` (this doesn't commit) and check `site/portfolio/`.

## Acceptance criteria
- A "Portfolio" tab appears in the site navigation.
- DCProof and toolstud.io are presented with descriptions and links taken from the blog.
- A curated set of GitHub projects is shown, grouped, each with its description and a GitHub link.
- The build finishes with "No issues found" and `site/portfolio/index.html` exists.
- No page in `site/` links to a missing internal page.
