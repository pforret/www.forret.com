# Add a README.md with a screenshot

## Request
add a README.md with a screenshot

## Analysis
The repo (`pforret/www.forret.com`) has no README, so its GitHub page shows nothing. A root
`README.md` sits outside `docs/`, so it is never published on the site. The screenshot also has to
live outside `docs/` (e.g. `.github/img/`) so it doesn't end up in `site/`.

`shot-scraper` is installed and can capture `https://www.forret.com/` (or the local `mkdox2 serve`
preview). Open question: light or dark scheme for the screenshot; default to light.

## Impacted files
- `README.md`: new, short description of the site, the stack (Zensical via `mkdox2`), how to
  preview/build/publish (summarised from `CLAUDE.md`), link to the live site, the screenshot
- `.github/img/screenshot.png`: new, homepage screenshot

## Plan
1. Capture the homepage: `shot-scraper https://www.forret.com/ -o .github/img/screenshot.png --width 1280 --height 800`.
2. Write `README.md`: title and link to https://www.forret.com/, the screenshot, what's in it
   (portfolio, CV, blog), commands (`mkdox2 serve`, `mkdox2 build` and its auto commit/push, the
   no-commit `docker run` build), and the publishing flow (`site/` committed, `pages.yml`).
3. Check the README renders on GitHub after a push (image path relative).

## Acceptance criteria
- `README.md` exists at the repo root and shows the screenshot on GitHub.
- Neither file appears in `site/` after a build.

## Notes
- [x] Screenshot captured from the live site (light scheme, 1280×800) into `.github/img/screenshot.png`.
- [x] `README.md` written: live link, screenshot, contents, stack, usage, publishing, layout.
- Both files are outside `docs/`, so the build can't pick them up; no test build needed.
- Still to check after the next push: the README renders on GitHub with the image.
