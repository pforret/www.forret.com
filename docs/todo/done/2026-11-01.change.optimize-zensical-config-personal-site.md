# Optimize zensical.toml for a founder / entrepreneur personal website

## Request
optimize @zensical.toml for a personal website of a founder / entrepreneur

## Analysis
This is a change: the config is the generic mkdox2 "documentation site" scaffold, and much of it reads as a docs site rather than a personal brand site. Findings, as checked on 2026-11-01:

**Identity and SEO** (shown in the title bar, OG and Twitter cards, search results and llms.txt):
- `site_name = "www.forret Docs"`, `site_description = "www.forret Docs by pforret"` and `copyright = "… www.forret Docs … built with mkdox"` all end up in `<meta name=description>`, `og:title` and `og:description` of every page (as seen in `site/index.html`). This is the most visible problem.
- No `site_author`, so there is no author meta tag.
- No `repo_url`; `theme.icon.repo` is Bitbucket, but the code is on GitHub.

**Look and feel:**
- `palette.primary = "red"` doesn't match the new blue "pf" favicon (#2196f3-ish, as on blog.forret.com). A blue or indigo palette would match.
- Only one palette, so there is no dark-mode toggle (`[[project.theme.palette]]` ×2 with `scheme = "default"/"slate"` and a toggle).
- Only `font.text = "Nunito"`. A `font.code` could be added (only used if code blocks appear).
- `logo` uses the 192 px icon. Fine, but the header shows `site_name` next to it, so the name matters.

**Features tuned for docs, not a portfolio:**
- `toc.integrate` plus `navigation.integrate` put the table of contents in the left sidebar. Pages here are short, so `toc.follow` or hiding the TOC on landing pages may fit better.
- `header.autohide`: hides the header with the tabs and the name while scrolling. Debatable for a personal site.
- `content.action.copy` ("copy page as Markdown" button) and `content.code.copy`: docs features; fine to keep or drop.
- `announce.dismiss` with `main.html`: the announcement block has already been emptied, so the feature does nothing now.
- Missing: `navigation.footer` (prev/next links), `navigation.top` (back-to-top), `navigation.indexes` (section index pages, e.g. `portfolio/index.md` as the tab page).

**Social and contact:**
- No `[project.extra.social]` links (LinkedIn, GitHub, blog, e-mail), which a personal site needs in the footer.

**Privacy and analytics:**
- `[project.extra.consent]` shows a cookie banner worded for "our documentation", while `analytics.provider = "custom"` loads an empty partial (`<!-- your analytics script -->`). So visitors get a cookie banner for cookies that don't exist. Either remove the consent and analytics config, or plug in a real privacy-friendly analytics service (Plausible, Umami, Cloudflare Web Analytics, …) and reword the banner.

**Possibly unused extensions:** `pymdownx.critic`, `caret`, `tilde`, `keys` and `tasklist` are harmless but unused. Removing them is optional cleanup.

Open questions:
- Site name: "Peter Forret", "forret.com", or something else? Tagline / description text?
- Colour: match the blue favicon (`blue` / `indigo`), or keep red?
- Dark mode toggle: yes or no?
- Analytics: none (drop the consent and analytics config), or which provider?
- Which social links to include (LinkedIn, GitHub, blog.forret.com, X, Mastodon, e-mail)?
- Keep the sidebar TOC and the autohiding header, or switch to a cleaner landing-page layout?

Risk: mkdox2 upgrades may regenerate `zensical.toml`, and the earlier upgrade already dropped a hand-added `exclude_docs` block. Keep the custom blocks clearly commented, and maybe note in `CLAUDE.md` which settings are hand-tuned.

## Impacted files

## PRP

### Goal
`zensical.toml` presents the site as **Peter Forret**'s personal brand site rather than a docs scaffold. Every page shows the right name, description and author in its title and its OG/Twitter meta tags. The theme is blue (matching the "pf" favicon) with a light/dark toggle that follows the OS. The layout is portfolio-style: sticky tabs, section index pages, TOC on the right, back-to-top button and previous/next footer, with no autohiding header. The footer has social links and "© 2004–2026 Peter Forret". Simple Analytics (cookieless) loads on every page, and there is no cookie banner.

### Why
- Link previews on LinkedIn and X, search results and browser tabs currently say "www.forret Docs by pforret". That's the first thing a prospect or client sees.
- The cookie banner currently asks consent for analytics that don't exist; Simple Analytics needs no consent.
- It ties in with the portfolio (B-item) and the coming About/CV page: same brand, same colours as blog.forret.com.

### Decisions taken
- Site identity → `site_name = "Peter Forret"`, `site_description = "Tech consultant and entrepreneur — founder of DCProof and toolstud.io, maker of open-source Bash tools"`, `site_author = "Peter Forret"` (user) (recorded: decisions/2026-11-01.brand-the-site-as-peter-forret.md)
- Colours → `primary = "blue"`, `accent = "blue"`, two palettes (`default`/`slate`) with a toggle following `prefers-color-scheme` (user) (recorded: decisions/2026-11-01.use-a-blue-palette-with-a.md)
- Analytics → Simple Analytics via the custom analytics partial (`<!-- 100% privacy-first analytics --><script async src="https://scripts.simpleanalyticscdn.com/latest.js"></script>` on every page), and no cookie banner, so `[project.extra.consent]` is removed (user) (recorded: decisions/2026-11-01.use-cookieless-simple-analytics-without-a.md)
- Social links → LinkedIn `https://www.linkedin.com/in/peterforret/` (not /in/pforret as on the blog), GitHub `https://github.com/pforret`, Blog `https://blog.forret.com/`, X `https://twitter.com/pforret`, YouTube `https://www.youtube.com/@PeterForret` (user) (recorded: decisions/2026-11-01.show-linkedin-github-blog-x-and.md)

### Known gotchas & guardrails
- Verified in a scratch build on 2026-11-01 (Zensical 0.0.74): this palette, social, features and custom-analytics set all build with "No issues found". The analytics partial is rendered without a consent block; the palette toggle renders "Switch to dark mode" / "Switch to light mode"; `<meta name=author>` is emitted.
- **Don't run `mkdox2 build`**; it commits and pushes, which publishes. Build with `docker run --platform linux/amd64 --rm -v "$PWD":/docs pforret/mkdox-zensical build`. Don't commit unless asked.
- PRESERVE: the `nav` list, `exclude_docs = """/todo/"""`, all `[project.plugins.*]` sections and every Markdown extension.
- Remove `[project.extra.consent]` (title + description) completely. Keep `[project.extra]` `generator = false` and `[project.extra.analytics] provider = "custom"`.
- The `privacy` plugin only self-hosts what's listed in `assets_include` (fonts, glightbox), so the Simple Analytics script stays remote, as it must. Don't add it to `assets_include`.
- Write the copyright with a real en dash and ©: `copyright = "© 2004–2026 Peter Forret"` (TOML is UTF-8; `&copy;` also works).
- The `social` plugin regenerates the OG card images in `site/assets/images/social/` with the new name. Expect many changed PNGs in `site/`.
- mkdox2 upgrades may regenerate `zensical.toml` (it happened once and dropped `exclude_docs`). Mark the hand-tuned blocks with a `# hand-tuned:` comment and list them in `CLAUDE.md`.
- Tags page: `tags.md` stays in `nav`; with `navigation.indexes` nothing changes for it.

### Approach

In `[project.theme]`: the features list per the decision, two `[[project.theme.palette]]` entries (light/dark, blue, with toggles), and the repo icon set to GitHub. Replace the `[project.extra.consent]` block with five `[[project.extra.social]]` entries. Put the Simple Analytics snippet in `custom.html`. Add a short "hand-tuned settings in zensical.toml" list to `CLAUDE.md` (identity, nav, exclude_docs, palette, features, social, analytics, privacy assets). Rebuild `site/` with the plain docker command.

### Discoveries
- The theme's palette CSS overrides `--md-footer-*` and `--md-typeset-a-color` at scheme level, and `.md-footer-meta` also has `.md-typeset`, so footer text and social icons took the dark ink colour until the variables were set on the footer elements plus a high-specificity rule for `.md-social__link`.
- The PRP check `grep 'github.com/pforret"'` fails on minified HTML (no attribute quotes); a Python parse is more reliable.
- The privacy plugin also self-hosts fonts pulled in by `@import` in `extra.css` (Work Sans), not only `theme.font`.
- The editorial h2 dot can read like a list bullet (recorded as a gotcha earlier); a candidate for a design tweak.
- The blue "pf" favicon now contrasts with the warm editorial palette; a recoloured favicon could be a follow-up.
