## PRP

### Goal
A **Portfolio** tab (second tab, after Home) presents Peter Forret's work. It has an overview with cards for three flagship projects (DCProof, toolstud.io, bashew), each with a detail page, and an "Open source" page that lists every non-fork, non-archived GitHub repo with ≥ 5 stars, grouped by theme. The open-source page is produced by a rerunnable script, `scripts/portfolio_repos.sh`, so the star counts can be refreshed before any build.

- The site exists to show Peter as a tech consultant and entrepreneur. The portfolio is the main showcase, next to the CV and About content (a separate item).
- It brings together content that now lives on the old blog (blog.forret.com/portfolio) and on GitHub.
- A generator keeps 27+ repo entries current without hand-editing.

### Known gotchas & guardrails
- **Never run `mkdox2 build`** (it commits and pushes, which publishes). Build with `docker run --platform linux/amd64 --rm -v "$PWD":/docs pforret/mkdox-zensical build`. Don't commit unless the user asks.
- `zensical.toml` has **no awesome-pages plugin**, so `.pages` files are ignored. Tab order comes only from `nav`. The `nav` list must include every top-level section (Home `index.md`, Portfolio pages, About `about/index.md`, Blog `blog/index.md`, Tags `tags.md`), or those pages drop out of navigation.
- Keep the `exclude_docs` block (`/todo/`) when editing `zensical.toml`. mkdox2 upgrades may regenerate the file.
- The generator must be **deterministic and idempotent**: sort groups in a fixed order and repos by stars (desc), then by name. Start the output with a `<!-- generated by scripts/portfolio_repos.sh on <date> — do not edit -->` comment. It writes only `docs/portfolio/opensource.md`.
- Escape `|`, `<` and `>` in repo descriptions (some contain them). Repos with no description get "–".
- Don't invent facts. DCProof and toolstud.io text comes from the blog (see Analysis); the role is "Founder", with no dates. bashew text comes from its GitHub README or description (`gh api repos/pforret/bashew --jq .description`, `gh api repos/pforret/bashew/readme -H 'Accept: application/vnd.github.raw'`).
- Group map, to use as the starting point (unmapped repos go under "Other"):
  - Bash frameworks & tools: bashew, setver, progressbar, rexec, note, shtext, shlorem, shini, shwordle, awk-boilerplate, bash_benchmarks, LearnBashQuickly
  - Sysadmin, network & macOS: m1_homebrew, crontask, glennr-unifi, wp_cleanup, bumpkeys, font, WinAdmin, netcheck, landeploy, ghlookup
  - Media & AI: splashmark, shmixcloud, m1fusion
  - Docs & developer tooling: mkdox, PeakClaude
- Images: download them with `curl -fsSL` into `docs/portfolio/img/` and reference them relatively (`img/dcproof.png`). glightbox is on, so they become click-to-enlarge.
- The `privacy` plugin downloads fonts on the first build; the "INFO [privacy] Downloading…" lines are normal.

### Approach
New folder `docs/portfolio/`: `index.md` (short intro, a `grid cards` block with DCProof, toolstud.io and bashew linking to their pages, plus a card "Open source on GitHub" → `opensource.md`), three detail pages and `img/`. New `scripts/portfolio_repos.sh` (bash with `set -euo pipefail`, needs `gh` and `jq`; `-h` prints usage). It fetches the repos, filters ≥ 5★ non-fork non-archived, assigns groups from its map, and writes `docs/portfolio/opensource.md` with one `##` section per group and a compact list or cards per repo (name as a GitHub link, ★ count, description, homepage link if set). Run it once so the file exists. In `zensical.toml`, add a `nav` list (Home, Portfolio [index, dcproof, toolstudio, bashew, opensource], About, Blog, Tags) and add `"Portfolio" = ["portfolio/*.md"]` to the llmstxt sections. Add a short "see my portfolio" link to `docs/index.md`. Document the regenerate command in `CLAUDE.md`.

### Validation loop (executable, in order)
```bash
# Level 1 — script syntax and behaviour
bash -n scripts/portfolio_repos.sh && (command -v shellcheck >/dev/null && shellcheck scripts/portfolio_repos.sh || echo "shellcheck not installed")
bash scripts/portfolio_repos.sh && head -3 docs/portfolio/opensource.md          # expect the generated marker
cp docs/portfolio/opensource.md /tmp/os1.md && bash scripts/portfolio_repos.sh && diff <(grep -v 'generated by' /tmp/os1.md) <(grep -v 'generated by' docs/portfolio/opensource.md) && echo "idempotent"
expected=$(gh api 'users/pforret/repos?per_page=100' --paginate --jq '[.[]|select(.fork==false and .archived==false and .stargazers_count>=5)]|length' | paste -sd+ - | bc)
found=$(grep -o 'github.com/pforret/[A-Za-z0-9_.-]*' docs/portfolio/opensource.md | sort -u | wc -l | tr -d ' ')
echo "expected $expected found $found"                                             # expect equal

# Level 2 — build
docker run --platform linux/amd64 --rm -v "$PWD":/docs pforret/mkdox-zensical build 2>&1 | tail -2   # expect "No issues found"
ls site/portfolio/{index.html,dcproof/index.html,toolstudio/index.html,bashew/index.html,opensource/index.html} site/portfolio/img/{dcproof.png,toolstudio.jpg}
test ! -e site/todo && echo "ok: todo excluded"

# Level 3 — content checks
grep -o 'md-tabs__link[^>]*>[^<]*<' site/index.html | sed 's/.*>//;s/<//' | xargs   # expect: Home Portfolio About Blog Tags
grep -c 'grid cards' site/portfolio/index.html                                     # expect ≥ 1
grep -c 'Founder' site/portfolio/dcproof/index.html site/portfolio/toolstudio/index.html   # expect ≥ 1 each
grep -c 'dcproof.net' site/portfolio/dcproof/index.html; grep -c 'toolstud.io/' site/portfolio/toolstudio/index.html   # expect ≥ 1
grep -c 'portfolio/' site/llms.txt                                                 # expect ≥ 1
```

### Confidence
**9/10** that this can be implemented in one pass by an agent with only this file and the repo.
What could still go wrong: repos that are new or renamed fall under "Other" until the group map is updated. That's harmless, but worth a look in the output.
